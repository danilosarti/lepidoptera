lepidoptera Causal simulation engine for structural causal models with mixed variable types

Separate the causal graph from the mechanism, declare any mix of continuous, ordinal, and categorical variables, then simulate populations, apply do-calculus interventions, and answer individual-level counterfactual queries — all in one pipe.

Continuous, ordinal, and categorical variables in any combination within the same DAG.

Minimal example

Age drives cardiovascular disease (CVD) risk through a logistic model. Four lines to define, one to simulate.

library("lepidoptera")

# Feature specs — declare name, type, bounds
age_spec <- feature_spec("age", "continuous",  list(min=18, max=100))
cvd_spec <- feature_spec("cvd", "categorical", list(levels=c("no", "yes")))

# Mechanisms — how each variable is generated
mech_age <- mechanism_library_get("normal")(mean=55, sd=12)
mech_cvd <- mechanism_library_get("multinomial_logit")(
  levels     = c("no", "yes"),
  coefs      = list(yes = list(age = 0.04)),
  intercepts = list(yes = -3.0)
)

# Assemble the causal system
sys <- new_system()                                 |>
  add_feature(age_spec)                             |>
  add_feature(cvd_spec)                             |>
  add_dependency(character(0), "age", mech_age)   |>
  add_dependency("age",        "cvd", mech_cvd)   |>
  finalize_system()

# Simulate 1 000 individuals
pop <- simulate(sys, n=1000, seed=1)
prop.table(table(pop$cvd))
cvd no yes 0.823 0.177
Interpretation
About 18% of the simulated population has CVD — consistent with the logistic model and an average age of 55. Run plot_dag(sys) to visualise the causal graph.

Core concepts

lepidoptera separates three concerns that are typically conflated in simulation code:

The three building blocks — define once, compose freely

A feature is a typed variable. A mechanism is the generating rule for that variable given its parents. A dependency wires them together into a DAG. finalize_system() validates the graph, checks type consistency, and computes the topological order for simulation.

Design principle
The same mechanism can be reused across systems. The same system can be queried with different interventions. Separation of concerns makes simulation code easy to audit and easy to extend.

Mechanism library

All built-in factories are accessed via mechanism_library_get(name), which returns a configuration function. Call it with the hyperparameters to get a mechanism ready to attach to a node.

NameVariable typeKey parameters
normalContinuous root nodemean, sd
categorical_marginalCategorical root nodelevels, probs
ordinal_marginalOrdinal root nodelevels, probs
linear_gaussianContinuous child — linear parentscoefs, intercept, sd
group_effectContinuous child — one categorical parentnamed list(mean, sd)
ordered_logitOrdinal childlevels, coefs, cutpoints
multinomial_logitCategorical childlevels, coefs, intercepts

Custom mechanisms

Write any R function that accepts a named list pv of parent values and returns one generated value, then register it with register_mechanism(). Ordinal parent values arrive as factors — cast with as.character() before switch(). 

my_fn <- function(pv) {
  mu <- 40 + as.numeric(pv$dose) * 8.2
  mu <- mu + switch(as.character(pv$arm),
    treatment=12, control=0, 0)
  rnorm(1, mu, sd=10)
}
mech_outcome <- register_mechanism(
  "outcome_linear", my_fn,
  parent_types = c("continuous", "categorical"),
  output_type  = "continuous"
)

Assemble & finalize

Chain everything with R's native pipe. finalize_system() validates the DAG and precomputes topological order.

trial_sys <- new_system() |>
  add_feature(feature_spec("age",       "continuous",  list(min=18, max=90))) |>
  add_feature(feature_spec("arm",       "categorical", list(levels=c("control","treatment")))) |>
  add_feature(feature_spec("severity",  "ordinal",     list(levels=c("mild","moderate","severe")))) |>
  add_feature(feature_spec("response",  "continuous",  list(min=0, max=100))) |>
  add_dependency(character(0),                          "age",      mech_age) |>
  add_dependency(character(0),                          "arm",      mech_arm) |>
  add_dependency("age",                                  "severity", mech_sev) |>
  add_dependency(c("age","arm","severity"),             "response", mech_resp) |>
  finalize_system()
Validation
finalize_system() throws an informative error if the DAG has a cycle, if a parent type doesn't match what a mechanism expects, or if a mechanism is missing for any declared node.

Simulate a population

simulate(system, n, seed) samples n units in topological order and returns a plain data frame.

pop <- simulate(sys, n=2000, seed=42)
head(pop)
plot_dag(sys)   # visualise the causal graph
Reproducibility
The same seed always produces the same population. Per-unit seeds are assigned internally, so adding more units doesn't reshuffle existing ones.

Interventions & propagation

propagate() applies one or more interventions, automatically recomputes all downstream variables, and returns $baseline and $intervened data frames. Upstream variables are unaffected.

InterventionWhat it does
do_fix(var, val)Fix the variable to a constant — classic do-calculus
shift(var, fn)Add a delta: fn(x) applied to the natural value
mechanism_override(var, fn)Swap out the entire generating rule
# Average Treatment Effect (ATE) — two independent populations
r_ate <- propagate(sys,
  interventions = list(do_fix("arm", "treatment")),
  n    = 2000,
  seed = 42,
  mode = "full"   # resample both worlds independently
)
mean(r_ate$intervened$response) - mean(r_ate$baseline$response)

# A relative shift — "what if every patient received 2 mg more?"
r_shift <- propagate(sys,
  interventions = list(shift("dose", function(x) x + 2)),
  n    = 2000,
  seed = 42,
  mode = "partial"
)

Counterfactual mode — Individual Treatment Effects

With mode="partial", unaffected nodes retain their baseline draws. The same individual appears in both potential worlds, enabling ITE estimation. 

# Same 1 000 people — what if everyone were 70?
result_cf <- propagate(
  sys,
  interventions = list(do_fix("age", 70)),
  n    = 1000,
  seed = 1,
  mode = "partial"
)

# Individual Treatment Effect for each person
ite <- (result_cf$intervened$cvd == "yes") -
       (result_cf$baseline$cvd  == "yes")
mean(ite)   # estimated ATE from counterfactual pairs
Mode comparison
Use mode="full" for population-level ATE (two independent draws). Use mode="partial" for individual-level ITE (same-unit counterfactual). The partial mode correctly handles paths through collider variables.

Vine copula mechanism

When observed data are available, copula_mechanism() fits the full joint dependence structure non-parametrically using D-vine copulas and uses it as the conditional generating rule at simulation time. This captures complex tail dependence and non-linear relationships that parametric models miss. 

library("rvinecopulib")  # required for copula_mechanism

# Observed blood pressure data
set.seed(42)
obs <- data.frame(sbp = rnorm(300, 130, 15))
obs$dbp <- 0.5 * obs$sbp + rnorm(300, 10, 8)

mech_dbp <- copula_mechanism(
  variables = c("dbp", "sbp"),
  family    = "auto",
  fit_data  = obs
)

sys_bp <- new_system()                     |>
  add_feature(feature_spec("sbp", "continuous", list(min=70,  max=250))) |>
  add_feature(feature_spec("dbp", "continuous", list(min=40,  max=150))) |>
  add_dependency(character(0), "sbp",
    mechanism_library_get("normal")(mean=130, sd=15)) |>
  add_dependency("sbp", "dbp", mech_dbp)            |>
  finalize_system()

sim_bp <- simulate(sys_bp, n=500, seed=7)

# Dependence preserved
cat(sprintf("Observed Spearman ρ: %.2f  |  Simulated: %.2f\n",
  cor(obs$sbp, obs$dbp, method="spearman"),
  cor(sim_bp$sbp, sim_bp$dbp, method="spearman")))
Observed Spearman ρ: 0.87 | Simulated: 0.86
D-vine algorithm
Internally, the mechanism fits a D-vine copula model on fit_data. At simulation time, given the realized parent values, the conditional quantile is obtained via sequential h-function inversion — preserving any non-linear and tail dependence present in the observed data.

Paper illustrations

The companion paper works through three illustrations that demonstrate lepidoptera across different application domains and variable-type combinations. See the arXiv preprint for full model specifications, code, and numerical results.

I

Clinical trial simulation

A randomised trial with treatment arm (categorical), baseline severity (ordinal), continuous biomarker response, and binary endpoint. The illustration shows how do_fix() on the arm node recovers the estimand of a per-protocol analysis and how mode="partial" produces individual-level response predictions for precision medicine use cases.

II

Emergency-ward digital twin

A five-node system encoding triage severity, wait time, treatment intensity, physiological trajectory, and 30-day readmission. The vine copula mechanism is fitted to anonymised emergency-ward records, preserving the observed tail dependence between wait time and adverse outcomes. The digital twin supports what-if capacity planning without repeated real-world data collection.

III

Epidemiological mediation analysis

Estimating natural direct and indirect effects in a mixed-type mediation graph: continuous exposure, ordinal mediator (physical activity level), and binary outcome (metabolic syndrome). mechanism_override() implements the mediation cross-world intervention, and mode="partial" recovers the individual-level decomposition.
