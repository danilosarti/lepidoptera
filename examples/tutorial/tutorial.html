Overview

What we're building

We'll simulate a student exam performance system — five causally connected variables that determine whether a student fails, passes, or earns a distinction.

The causal story: preparation time and prior knowledge jointly produce fatigue and an exam score, which is then mapped to an outcome grade.

Causal DAG — arrows show which variables influence which
Why this example?
Five nodes, all three feature types, a clear causal story, and no domain expertise required. Every lepidoptera concept appears at least once.

Step 3

Declare the DAG

The DAG is the causal skeleton, declared with add_dependency(parents, child, mechanism).

  • Root nodes (no parents) use character(0) as the parent list.
  • Every feature must appear exactly once as the child argument.
# parents                        child               mechanism
add_dependency(character(0),                "study_hours",    …)
add_dependency(character(0),                "prior_knowledge",…)
add_dependency("study_hours",              "fatigue",        …)
add_dependency(c("study_hours",
               "prior_knowledge",
               "fatigue"),               "exam_score",     …)
add_dependency("exam_score",              "outcome",        …)
Acyclicity
lepidoptera validates the DAG on finalize_system() with Kahn's algorithm. A cycle produces a descriptive error before any simulation runs.
Step 4

Mechanisms for root nodes

A mechanism is the generating function for a feature. Root nodes have no parents, so their mechanisms are marginal distributions — call a factory with mechanism_library_get("name")(…params…).

FactoryUse forKey params
normalContinuous, bell-shaped rootmean, sd
categorical_marginalCategorical root nodelevels, probs
ordinal_marginalOrdinal root nodelevels, probs
linear_gaussianContinuous child, linear parentscoefs, intercept, sd
group_effectContinuous child, one categorical parentnamed list(mean, sd)
ordered_logitOrdinal childlevels, coefs, cutpoints
multinomial_logitCategorical childlevels, coefs
# study_hours: average ~7 h, sd = 3 h
mech_study_hours <- mechanism_library_get("normal")(mean=7, sd=3)

# prior_knowledge: 30 % low, 50 % medium, 20 % high
mech_prior <- mechanism_library_get("ordinal_marginal")(
  levels = c("low", "medium", "high"),
  probs  = c(0.3, 0.5, 0.2)
)
Step 5

Mechanisms for dependent nodes (built-in)

fatigue is ordinal with one continuous parent. ordered_logit fits: more study hours → higher probability of high fatigue.

mech_fatigue <- mechanism_library_get("ordered_logit")(
  levels    = c("low", "moderate", "high"),
  coefs     = list(study_hours = 0.30),
  cutpoints = c(1.5, 3.2)
)
Step 6

Write a custom mechanism

When no built-in factory covers your parent-type combination, write an R function and register it. The function receives a named list pv (parent values) and returns one generated value.

Anatomy of a custom mechanism — pv holds all parent values by name

exam_score ← study_hours + prior_knowledge + fatigue

score_fn <- function(pv) {
  # baseline from study time
  mu <- 40 + as.numeric(pv$study_hours) * 4.5
  # ordinal → as.character() before switch()
  mu <- mu + switch(as.character(pv$prior_knowledge),
    low=-10, medium=0, high=+10, 0)
  mu <- mu + switch(as.character(pv$fatigue),
    low=0, moderate=-5, high=-15, 0)
  pmin(100, pmax(0, rnorm(1, mu, sd=8)))
}
mech_score <- register_mechanism(
  "score_from_study_knowledge_fatigue", score_fn,
  parent_types=c("continuous","ordinal","ordinal"),
  output_type="continuous"
)

outcome ← exam_score

outcome_fn <- function(pv) {
  s <- as.numeric(pv$exam_score)
  if      (s >= 75) "distinction"
  else if (s >= 50) "pass"
  else              "fail"
}
mech_outcome <- register_mechanism(
  "outcome_from_score", outcome_fn,
  parent_types="continuous", output_type="categorical"
)
The pv contract
pv is a named list. Ordinal values arrive as factors — cast with as.character() before switch(). Continuous values arrive as numeric — cast with as.numeric() for safety.
Step 7

Assemble & finalize

Chain everything with R's pipe operator. finalize_system() validates the DAG, checks type consistency, and computes the topological order.

Full lepidoptera workflow — define once, run many times
exam_sys <- new_system() |>
  add_feature(feature_spec("study_hours",    "continuous", list(min=0,max=20))) |>
  add_feature(feature_spec("prior_knowledge","ordinal",list(levels=c("low","medium","high")))) |>
  add_feature(feature_spec("fatigue",        "ordinal",list(levels=c("low","moderate","high")))) |>
  add_feature(feature_spec("exam_score",     "continuous",list(min=0,max=100))) |>
  add_feature(feature_spec("outcome",        "categorical",list(levels=c("fail","pass","distinction")))) |>
  add_dependency(character(0),                                  "study_hours",    mech_study_hours) |>
  add_dependency(character(0),                                  "prior_knowledge",mech_prior) |>
  add_dependency("study_hours",                                 "fatigue",        mech_fatigue) |>
  add_dependency(c("study_hours","prior_knowledge","fatigue"), "exam_score",     mech_score) |>
  add_dependency("exam_score",                                  "outcome",        mech_outcome) |>
  finalize_system()
Step 8

Simulate a population

simulate(system, n, seed) samples n units in topological order and returns a plain data frame.

df <- simulate(exam_sys, n=1000, seed=42)
head(df)

Reproducibility
The same seed always produces the same population. Per-unit seeds are assigned internally, so adding units doesn't reshuffle existing ones.

Step 10

Apply an intervention

An intervention surgically alters one or more nodes and propagates the change automatically through all downstream variables. Everything upstream stays exactly as it was.

modeWhat it doesUse when
partialReuses the same baseline draws for unaffected nodesCounterfactual ("same students, more study time")
fullResamples the entire intervened system independentlyPopulation comparison (different cohorts)
do_fix("study_hours", 12) fixes the target and recomputes all downstream variables — prior_knowledge is upstream and stays untouched
r <- propagate(exam_sys,
  interventions = list(do_fix("study_hours", 12)),
  n    = 1000,
  seed = 42,
  mode = "partial"
)
# r$baseline          → original population
# r$intervened        → same students under intervention
# r$affected_features → c("fatigue","exam_score","outcome")
Step 11

Compare baseline vs. intervened

compare(r) returns a named list — access any variable by name.

delta <- compare(r)

print(delta[["exam_score"]])  # continuous: mean shift
print(delta[["outcome"]])    # categorical: freq shift

# Or compute directly:
prop.table(table(r$baseline$outcome))
prop.table(table(r$intervened$outcome))
$exam_score$baseline_mean → 66.4 $exam_score$intervened_mean → 84.1 $exam_score$mean_diff → +17.7 fail pass distinction baseline 28.7% 48.9% 22.4% intervened 4.1% 31.3% 64.6%
Interpretation
Fixing study hours to 12 raises the mean score by 17.7 points and triples the distinction rate (22% → 65%). The effect flows through fatigue too — more study → more fatigue → partial score penalty, which mode="partial" captures correctly.
Step 12

More interventions at a glance

shift() — relative change

Adds a delta to the value the mechanism would naturally produce. The causal structure above the node is preserved.

# "What if every student studied 3 h more than normal?"
propagate(exam_sys,
  interventions=list(shift("study_hours", function(x) x + 3)),
  n=1000, seed=42, mode="partial")

mechanism_override() — replace the generating rule

Swaps out an entire mechanism for a node. The parent set is preserved; only the function changes.

# "What if prior_knowledge had zero effect on exam_score?"
no_prior_fn <- function(pv)
  pmin(100, pmax(0, 40 + as.numeric(pv$study_hours)*4.5 + rnorm(1,0,8)))

propagate(exam_sys,
  interventions=list(mechanism_override("exam_score",
    register_mechanism("no_prior", no_prior_fn,
      c("continuous","ordinal","ordinal"), "continuous"))),
  n=1000, seed=42, mode="full")

Multiple interventions at once

# "Best-case: 12 h study AND high prior knowledge"
propagate(exam_sys,
  interventions=list(
    do_fix("study_hours",    12),
    do_fix("prior_knowledge", "high")
  ),
  n=1000, seed=42, mode="partial")

Step 13

Counterfactual reasoning — the individual "what if?"

An intervention asks: "If we gave everyone 10 study hours, how would the population change?" — a new group of students, subject to the new rule.

A counterfactual asks: "What would THIS specific failing student have scored, if they had studied 10 hours instead of their actual 4?" — the same individual, a different past.

The key difference is mode = "partial". It freezes every unaffected attribute — prior knowledge, the random noise in fatigue, the noise in the exam score — and replays only what downstream of the intervention changes. Each student's "luck" stays fixed. Only the intervention variable and its consequences are rewritten.

Same student — two worlds. The prior knowledge and individual noise stay identical; only study_hours and its downstream consequences change.

Code

# Step 1: baseline simulation (already done in Step 8)
#   df <- simulate(exam_sys, n = 1000, seed = 42)

# Step 2: counterfactual — same individuals, study_hours fixed to 10
r_cf <- propagate(exam_sys,
  interventions = list(do_fix("study_hours", 10)),
  n    = 1000,
  seed = 42,
  mode = "partial"  # ← this is what makes it counterfactual
)

# Step 3: among students who actually FAILED, what would have happened?
actually_failed <- r_cf$baseline$outcome == "fail"
cf_outcomes     <- r_cf$intervened$outcome[actually_failed]

cat(sprintf("Among %d students who actually failed:\n",
            sum(actually_failed)))
cat(sprintf("  would still fail:       %d (%.0f%%)\n",
    sum(cf_outcomes == "fail"),        mean(cf_outcomes == "fail")        * 100))
cat(sprintf("  would pass:             %d (%.0f%%)\n",
    sum(cf_outcomes == "pass"),        mean(cf_outcomes == "pass")        * 100))
cat(sprintf("  would get distinction:  %d (%.0f%%)\n",
    sum(cf_outcomes == "distinction"), mean(cf_outcomes == "distinction") * 100))

# Step 4: zoom in on one specific student
i <- which(actually_failed)[1]   # first student who failed

cat(sprintf("\nStudent #%d — what actually happened:\n", i))
print(r_cf$baseline[i, ])

cat(sprintf("Student #%d — counterfactual (study = 10 h):\n", i))
print(r_cf$intervened[i, ])
Among 287 students who actually failed: would still fail: 48 (17%) would pass: 186 (65%) would get distinction: 53 (18%) Student #3 — what actually happened: study_hours prior_knowledge fatigue exam_score outcome 3 2.11 low high 28.4 fail Student #3 — counterfactual (study = 10 h): study_hours prior_knowledge fatigue exam_score outcome 3 10.0 low high 61.8 pass
What this tells us
Student #3 had low prior knowledge and suffered high fatigue even with 10 hours — yet the score jumped from 28 to 62 and they would have passed. Their prior knowledge stayed low, their luck with fatigue stayed bad, but the extra study time was enough. 83% of failing students would have changed outcome — and the 17% who would still fail are those for whom structural disadvantage (very low prior knowledge + high fatigue) overwhelms the study effort.

Step 14

Copula mechanism — dependence structure from data

So far every mechanism was hand-specified: you chose the distribution family and its parameters yourself. copula_mechanism() takes a different path — give it a data frame and it learns the full joint dependence structure for you, then uses it to generate the child variable conditional on any combination of parent values.

Under the hood, lepidoptera fits a pair-copula construction (D-vine) via rvinecopulib. Variables are ordered c(parents…, child) so that the Rosenblatt transform gives v[last] = F(u_child | u_parents) — a quantity that can be inverted exactly to sample one fresh child value per unit.

Families available — pass any of these as family =:
family = what it does
"gaussian"Gaussian copula, base R only — no extra packages needed
"auto"Best family per pair, chosen by AIC (rvinecopulib); falls back to Gaussian if not installed
"t"Student-t — heavier joint tails than Gaussian
"clayton"Strong lower-tail dependence (co-movement in bad times)
"gumbel"Strong upper-tail dependence (co-movement in good times)
"frank"Symmetric tails, no tail dependence
"joe", "bb1"…"bb8"Parametric Archimedean families and two-parameter extensions
"tll"Non-parametric kernel (transformation local likelihood)
 
# Suppose we observed exam scores alongside hours slept the night before.
# We want the simulation to honour the correlation structure in the data.

## Step 1 — gather observed data (here we manufacture some)
set.seed(1)
n_obs   <- 400
obs_data <- data.frame(
  study_hours = rnorm(n_obs, 6, 2),
  sleep_hours = rnorm(n_obs, 7, 1.2)
)
# make them correlated (students who study more tend to sleep less)
obs_data$sleep_hours <- obs_data$sleep_hours - 0.4 * obs_data$study_hours + rnorm(n_obs, 0, .8)

## Step 2 — fit a copula mechanism for sleep_hours | study_hours
library(lepidoptera)

mech_sleep <- copula_mechanism(
  variables = c("sleep_hours", "study_hours"),  # child first, parents after
  family   = "auto",                             # best-fit family per pair
  fit_data = obs_data
)

## Step 3 — plug it into any system like any other mechanism
mech_study <- mechanism_library_get("normal")(mean = 6, sd = 2)

sys_cop <- new_system() |>
  add_feature(feature_spec("study_hours", "continuous", list(min=0, max=24))) |>
  add_feature(feature_spec("sleep_hours",  "continuous", list(min=0, max=24))) |>
  add_dependency(character(0),      "study_hours", mech_study) |>
  add_dependency("study_hours",     "sleep_hours", mech_sleep) |>
  finalize_system()

sim_cop <- simulate(sys_cop, n=600, seed=42)

cor(sim_cop$study_hours, sim_cop$sleep_hours, method="spearman")
# > [1] -0.37   ← recovers the negative correlation from obs_data

## What families are available on your installation?
list_copula_families()
When to use a copula vs. a parametric mechanism. Use copula_mechanism() when you have real data and want the simulation to honour its dependence structure — shape of tails, asymmetry, multivariate co-movement — without having to specify a functional form by hand. Parametric mechanisms (linear_gaussian, multinomial_logit, …) are better when you want to reason explicitly about the structural equation: slope, intercept, noise scale.
Step 15

model_mechanism — wrap any pre-fitted model

You trained a random forest yesterday. A colleague fitted a logistic regression on clinical data. model_mechanism() lets you drop any pre-existing model object directly into a lepidoptera system as a generative mechanism — no re-training, no adapter code.

The contract is a single function predict_fn(parent_values) that receives a named list of parent values and returns one simulated value. You write the translation layer (reformatting inputs, picking the right output slot, adding residual noise if needed). To the system, this node is completely ordinary.

learned_mechanism

Fits its own model internally from fit_data. Good when you want lepidoptera to learn the relationship automatically (OLS, k-NN). No external package needed.

model_mechanism

Uses a model you already trained (ranger, xgboost, keras, glm, …). You control the prediction logic. Best for production-grade models or complex architectures.

## Example 1 — lm as a generative mechanism (adds residual noise)
set.seed(7)
df_fit <- data.frame(age=rnorm(200,50,10), sbp=rnorm(200,120,15))
fit_lm <- lm(sbp ~ age, data=df_fit)
sigma  <- summary(fit_lm)$sigma

mech_sbp <- model_mechanism(
  predict_fn = function(pv) {
    nd   <- data.frame(age=as.numeric(pv$age))
    pred <- predict(fit_lm, nd)[[1L]]
    pred + rnorm(1, 0, sigma)   # ← you add noise explicitly
  },
  parents      = "age",
  parent_types = "continuous",
  output_type  = "continuous"
)

The predict_fn is the integration boundary. Inside it you can call any R package — ranger, xgboost, keras, torch, a REST API — as long as it takes parent values and returns one value. lepidoptera never sees the model object; it only sees the function. This means you can swap models without touching the system definition.
